# 个人知识库备份实施计划

对应 FR-030；当前实现有限范围的版本化导出、预览和导入为新数据，不能称为完整知识库恢复。

## 格式和范围

- JSON `zhiyan-personal-export` 版本 4，在版本 3 范围上增加有效卡片和草稿的手动证据关联及变更历史，包括已移除的关联。回收站内文献及其笔记不包含在内。
- 不包含 PDF 附件、回收站数据及计划中回收文献的关联、回收站对象自身的证据、工作流、通知、账户、会话和 AI 配置。草稿和手动证据中不在本次备份的来源保留内容快照，导入后编号为空并标记不可用；不凭旧编号关联目标账号的既有数据。来源含当前格式不支持的字段时导出拒绝，不静默丢弃。文件不会纳入密码散列、登录令牌、API Key 或服务端密钥字段；自由文本可能含用户自行输入的敏感信息，需妥善保存。
- 单份 JSON 上限 10 MiB。只读预览检查大小、版本、JSON 结构、重复编号和本格式已定义的关联引用；此检查不表示文件已具备完整恢复能力。
- PDF 可单独导出和导入 ZIP 附件包，最多 100 个、总计 50 MiB，并验证文件头、大小及散列；恢复需手动将原文献映射到本人目标文献，不与 JSON 自动恢复关联，也不自动合并重复附件。仅支持同一主机及支持硬链接的同卷存储；故障与验收限制见 `PDF附件备份设计.md`。

## 现有导入策略与限制

恢复前检查字段、引用、数量和标签重名；预览后导入时重新校验并要求确认，文件摘要不一致时拒绝。所有对象分配新 ID，关联仅映射文件内对象，不指向目标账号既有数据。文献和卡片可能重复创建，不自动识别或合并；标签名称规范化后如与现有标签冲突，整批拒绝。数据库导入为单事务，异常回滚，不触发既有工作流。导入对象的创建/更新时间为导入时生成，原始时间及状态变更历史不保留；卡片历史保留内容和版本号，但版本创建时间不保留。旧版本快照中无法映射的文献引用标记不可用。

## 用户操作

1. 在“个人数据备份”选择“导出个人数据”，安全保存 JSON；文件不加密，文献、笔记和 URL 可能包含用户自行输入的敏感内容。
2. 在目标账号选择同一文件并预览，核对数量、未包含范围和标签冲突。预览仅针对当前文件和账号；若文件或现有标签发生变化，请重新预览。
3. 确认后导入为新数据；失败时界面显示原因，数据库写入异常按事务回滚。重复导入可能产生重复文献、卡片和项目，标签冲突会阻止整批导入。

支持本平台版本 1 至 4 JSON；版本 1 没有结构化笔记和模板，版本 1、2 没有计划和草稿，版本 1 至 3 没有手动证据及其历史，预览显示各自的缺失范围。同名自定义模板作为独立模板新建；结构化笔记、计划文献、项目及证据关联映射到导入后新编号。证据历史保留时间、内容及动作，来源编号按本次导入结果重映射。不能导入压缩包和附件，不支持其他版本或其他平台格式。当前仅验证所列范围的代表性数据，浏览器交互和大规模数据恢复尚未验收。
