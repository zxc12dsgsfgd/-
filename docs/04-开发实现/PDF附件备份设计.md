# PDF 附件备份设计

> 状态更新（2026-11-21）：现已实现 PDF 附件导入及未完成批次的手动清理；下方早期阶段记录按当时状态保留，最新能力与限制以文末“导入实现与验证”为准。

目标：扩展个人数据备份，覆盖本人有效文献的 PDF。文件系统与 MySQL 无法组成单一原子事务，不能把数据库回滚误称为文件恢复成功。

本阶段实现独立 PDF 附件包导出，不提供附件导入：ZIP 内仅使用系统生成的 `files/<编号>.pdf` 相对路径和版本化 `manifest.json`，清单记录来源文献编号、原始名称、长度及 SHA-256；导出前逐个校验所属账户、存储状态、大小、PDF 文件头和散列，任一失败则整包拒绝。最多 100 个文件、单个不超过项目 PDF 限额、附件总计 50 MiB；不包含回收站文献附件。附件与 JSON 备份需要一起安全保存，但目前没有自动关联恢复能力。文件不加密。

现已实现只读附件包预览：限制压缩包大小、条目数量和解压后大小，只接受本平台生成的无压缩条目，拒绝绝对路径、上级路径、重复项、软链接、加密项及未声明文件；校验 PDF 文件头、长度和散列。预览不写入文件，也不验证目标文献映射。

新增只读映射核对：用户为每个原文献显式填写目标文献编号，服务端重新校验附件包摘要及所有目标归属，显示目标标题和附件数量；映射不保存、不写入附件。

映射核对返回基于当前会话、附件包 SHA-256 和规范化映射的 HMAC 凭据。未来导入接口应重新校验附件与目标归属，并以常量时间比较凭据；不能只相信客户端提交的摘要或编号。凭据只绑定会话及映射，不代表导入已完成，也不代替用户最终确认。

拟议的导入持久化边界：先在数据库事务中锁定并复核目标文献，再为每个待导入文件分配服务端随机键，持久化导入批次和预留文件清单后才写文件；清单记录批次、所有者、目标文献、键、期望长度与散列及状态，不能使用压缩包路径作为磁盘路径。文件写入和校验完成后，用数据库事务将文件记录统一转为可访问状态并标记批次完成。若进程在文件写入期间终止，持久化清单须保留，恢复程序只操作清单中的随机键，并在清理或重试前重新锁定批次；禁止扫描、删除未登记文件。数据库提交结果不确定时先重新读取批次状态，再决定是否清理，防止误删已经提交的文件。需要对清理失败、进程终止、重复提交和并发恢复逐个故障注入后再开放导入。

附件恢复尚未实现。后续必须使用随机受控路径暂存，并明确写入数据库和文件的顺序、崩溃恢复及重试策略；只有实际故障注入及隔离环境验证后才能开放恢复。不得把附件包描述为可完整恢复的备份。

## 导入预留基础（2026-11-21）

已加入内部批次及附件预留表、归属校验与登记文件清理函数；预留前检查附件数、名称、散列和总大小。清理仅接受明确标记为 `aborted` 的本人批次，检查登记键未被附件记录引用后逐个删除；中途失败保留状态以便重试。该代码没有公开接口，也没有自动将批次判定为中止的机制。

自动化测试覆盖跨账号拒绝、非中止批次拒绝、非登记文件保护、清理失败及部分清理后重试。隔离 MySQL 从旧版本迁移至 `0026_pdf_import` 成功；实际写入、真实进程崩溃、并发竞争和提交结果不确定时的恢复均未验证。预留表对文献有外键，未完成批次与永久删除的协调规则尚未实现；导入开放前还须解决文件键占用、活跃导入进程识别及清理与提交之间的竞争，不能仅凭当前内部函数认为清理安全。

## 内部暂存写入（2026-11-21）

新增内部暂存函数：在持有批次行锁期间验证所有文件的清单编号、PDF 文件头、长度与散列，然后在受控根目录下独占创建批次目录及随机键文件，写入并对文件执行 flush 和 fsync。目录已存在则拒绝覆盖；写入失败时保留部分文件和预留状态，不将其作为可用附件发布。测试使用临时目录与 SQLite，覆盖跨账号、内容篡改、目录占用和模拟 fsync 失败；这不等于真实进程中断或 MySQL 并发验证。

暂存函数尚无公开调用方或状态转换；调用方必须在写入期间保持数据库事务，并在异常后回滚。现有 `cleanup_aborted` 针对最终附件目录，不负责此暂存目录，不能用于清理暂存文件。暂存目录的可信所有权、清理及重试协议、目录项持久性、进程存活判定、数据库提交不确定处理和发布步骤仍待实现与故障验证；故不得开放附件导入。

## 中止批次暂存清理基础（2026-11-21）

暂存目录创建后写入批次标记。新的内部清理函数只接受本人已标为 `aborted` 的批次，并在持锁期间检查目录标记及登记文件名；发现陌生条目、符号链接或非普通文件则拒绝清理。已删除的登记文件可在重试时缺席；清理失败不改变批次状态。清理暂存目录和清理最终附件是不同操作，本函数不会将批次标为 `cleaned`。

前提是暂存根目录及其所有上级路径由应用独占控制，标记本身不是防止本机恶意写入的认证机制，路径检查也不提供对本机并发替换的防护。创建目录后、标记写入完成前中断，或删除标记后、目录移除前中断，可能留下无法自动确认归属的目录；必须拒绝自动清理并留待后续恢复机制处理。批次何时可安全标记为中止、跨进程互斥、数据库提交结果不确定与最终文件清理的联动仍未实现；当前仅在 SQLite 和临时目录下模拟测试，不可对外开放。

## 批次中止协调（2026-11-21）

内部 `abort_batch` 使用数据库行锁，在所有者匹配且状态为 `reserved` 时提交 `aborted`；对已中止批次重复调用可安全返回，对完成或其他状态拒绝。它不负责清理，也不自动判断应该何时中止。使用隔离 MySQL、两条数据库连接和应用实际暂存函数，观察到中止请求等待目标批次行锁，写入方释放锁后中止并清理合成暂存文件；临时库、授权及文件已清理。

此结论依赖所有现有及未来写入方在实际文件操作期间持有同一行锁，且释放锁后不再写入。尚未验证真实进程被终止、数据库断连或提交结果不确定；这些场景须重新读取持久状态，不得凭异常直接清理。暂存与最终附件的清理协调、发布、去重和恢复接口仍未实现，附件导入继续关闭。

## 导入实现与验证（2026-11-21）

附件包在界面选择并校验后，逐个将原文献编号映射到当前账号的目标文献；核对标题、附件数并确认后，服务器重新验证包、映射、会话凭据和归属，将文件作为新附件导入，不覆盖或自动合并已有文件。同一请求编号重复提交返回原结果；若请求结果未知，页面保留编号供重试，并提供本人未完成批次的中止清理。批次未完成时永久删除关联文献会被拒绝，处理完毕后可删除。

写入先保留数据库清单，在独占批次暂存目录验证并写入；发布使用同卷硬链接，目标存在即失败，不覆盖其他文件；附件记录与完成状态在同一数据库事务中提交。未完成批次恢复只删除能够通过文件身份确认属于该批次的硬链接；发现冲突、未知目录内容或标记异常时保留现场并提示人工处理。提交结果不确定时必须重新查询数据库；清理仅对确定中止或完成的批次执行。批次操作还使用本机跨进程锁，避免数据库连接提前断开时仍有文件写入与清理重叠；锁文件保留在应用受控目录。

部署限制：仅支持同一主机上的应用进程共享本机锁和同卷、支持硬链接的受控存储；不支持多主机共享存储部署。若文件系统不支持硬链接，导入失败并保留待处理批次。暂存目录及上级目录必须由应用独占控制；目录创建或标记删除瞬间中断时，可能需要人工检查。应用不会保证整机掉电时目录项持久性，也没有后台自动清理；PDF 校验只检查文件头、长度和散列，不证明内容完整或安全。附件 ZIP 和 JSON 须分别保存、恢复时手动映射，不能宣称完整恢复全部系统数据。

验证：95 项后端测试和前端构建通过；隔离 MySQL 验证双账号导出、映射、导入、重复请求、越权拒绝和文献永久删除。隔离 MySQL 在暂存后、发布前提交和发布完成提交后分别强制终止真实进程，检查中止清理或已提交附件保留；另以两个真实 Windows 进程验证本机锁竞争及持锁进程退出后释放。临时库、授权和测试文件均已清理。未完成真实数据库断连组合故障、断电、浏览器端到端和多主机验证。
