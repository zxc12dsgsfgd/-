# 回收站实施计划

对应 FR-031；先实现卡片，再分别实施文献和研究项目。各阶段未完成前不将整项需求标记完成。

## 卡片处理规则

- 普通删除将卡片标记为已删除，保留历史版本、标签、卡片关系、项目关联和证据记录；正常列表、详情、搜索、图谱、项目统计、导出、AI 选材、标签操作和新增分享不得把回收站卡片当作有效数据。原有分享为独立快照，删除卡片不会自动撤销分享；用户需在分享管理主动撤销。已撤销分享不会因恢复卡片而重新启用。
- 回收站仅返回当前账户的已删除卡片，可恢复；恢复后仍存在的关联重新可见。如果关联对象在此期间被删除，依据该对象删除规则处理，不保证关系可恢复。永久删除前展示不可恢复提示和影响，要求显式确认；服务端再次校验拥有者并在事务内清理关联及历史。
- 当前不设置自动清理，默认无限期保留；界面和文档明确说明。回收站不是备份，PDF 附件尚不在本阶段处理范围。
- 检查读取及写入的每个卡片入口，避免回收站绕过授权；通过多用户、关联恢复、原分享撤销、并发和备份排除测试；隔离 MySQL 验证迁移和业务流程。

## 研究项目处理规则

- 项目普通删除改为进入回收站，项目及其文献、卡片、阅读计划和草稿关联暂时保留；不删除原资料。正常项目列表、接口和个人数据备份排除回收中的项目及其关联。
- 恢复项目后，其间仍存在且当前可访问的关联重新显示；被永久删除的源数据不能通过恢复项目找回。项目状态保持删除前的进行中、已完成或已归档。回收站项目默认无限期保留，未实现自动清理。
- 仅所有者能查看、恢复和经明确确认后永久删除。永久删除只删除项目和关联，不删除文献、卡片、阅读计划或草稿；与数据库内关联清理同一事务。

## 文献及 PDF 处理规则

- 普通删除把文献移入回收站，文献、PDF、笔记、标签、阅读计划及项目关联保留；正常文献、文件、计划统计、AI、导出和工作流入口排除该文献。关联卡片保留，来源暂标记不可用并保留快照；恢复文献后仍关联的卡片来源重新可用，用户核查状态不自动恢复。
- 永久删除之前必须分别确认清除该文献的每个 PDF；清除失败保留 `deleting` 文件记录并允许重试，在文件清理进行中拒绝恢复文献。全部文件清除后，再确认永久删除文献：数据库事务删除笔记和关联，卡片断开来源并保留快照。文件系统与数据库不能组成原子事务，成功清除的 PDF 无法通过恢复文献找回；页面明确提示。文件路径只使用现有的随机受控存储键。
- 文献回收默认无限期保留，不自动清理。永久删除不能恢复，已有草稿及分享快照仍遵循原有快照和撤销规则。回收站不是备份。
