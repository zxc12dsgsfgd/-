# 证据链实施计划

对应 FR-029；先实现卡片分类和用户核查状态，再实现草稿来源编辑、变更记录和失效提示。旧内容来源不能推断为原文、AI 或已核实，迁移设为“未分类、待核查”。

1. 卡片保留正文并允许用户选择正文性质：未分类、用户解释、AI 建议、用户结论；已有来源原文和备注字段继续独立。四种核查状态为待核查、用户标记已核查、存疑和已废弃；用户自行核查不意味着系统保证。
2. 卡片保存、编辑和历史快照包含分类与核查状态；兼容旧客户端省略新字段时保留已有值。正文、类别、来源位置、原文或备注变更时，如状态为用户标记已核查，则重置为待核查；用户可在保存内容后单独重新核查。文献删除和手动解除时保留标题快照并提示原来源不可用或已解除，避免断链被静默隐藏。
3. 草稿的实际选材快照不可被修改为其他内容；单独设计可增删的来源关联和变更历史，明确选材快照与当前关联之差异以及源已删除/不可用的状态；只在服务端授权后关联本人材料。
4. 先以测试客户端验证老数据兼容、状态保存、历史、断链和双账号隔离，再以隔离 MySQL 验证迁移，最后测试界面。数据库版本升级、范围及未完成部分记录在需求矩阵和测试记录。

## 多来源关联实施约定（2026-11-20）

- 为卡片和草稿增加独立的手动来源关联及追加式变更记录。关联支持本人文献或卡片，保存当时的标题、DOI/链接快照、位置、原文和备注；不能关联自身或他人资源。用户编辑位置、原文和备注，移除采用标记保留历史，不更改源对象。
- 草稿原始 `sources` 保持不可变，以区别创建/发送时实际材料与用户后来增加的关联；旧卡片的单一文献来源仍按原方式显示，手动关联为额外来源。每项读取按当前拥有者查验源存在性，失效时只返回保存的快照，不跨账号查找或暴露数据。
- 新增、编辑、移除均与历史记录同事务；影响卡片来源时将用户已核查状态重置并新增卡片版本，影响已接受草稿时恢复待审核。以 50 条有效关联为限；删除卡片或草稿时其手动关联及历史随该对象删除。
