## 执行顺序

1. 核对缺口及运行环境，建立可追溯测试数据；先处理会阻断核心验收的已知未实现项。
2. 运行自动化测试及前端构建，保留命令、时间、结果和限制；根据失败诊断并复测。
3. 用两账号执行浏览器业务链路、导出与独立访客分享；逐项填写实际结果，涵盖正常、异常和权限边界。
4. 使用真实 MySQL 检查迁移、数据持久化与工作流/worker；空库迁移只在单独隔离的临时数据库执行，避免修改现有数据。
5. 单独验证 AI 外部服务、安全与多进程边界；缺条件标记阻塞，不推断为通过。
6. 汇总缺陷、修复及复测；全部适用 P0 通过且未解决风险可接受后，再开展部署与用户验收。

## 通过与退出标准

- 测试状态仅使用未执行、通过、失败、阻塞；通过须记录实际结果与证据。
- 测试套件通过不代表所有首版需求通过；单次模拟或 SQLite 测试不能替代真实 MySQL、浏览器及真实外部服务验证。
- P0 未实现或失败应登记缺陷并修复复测；P1 按首版范围继续完成，不默认延期。外部条件缺失应单列，不得宣布整体验收通过。
- 关注安全：访问控制、令牌有效期及撤销、密钥不泄露、输入安全、上传边界、出站地址及限流；现有单进程限制和生产安全审查不得被当作已解决。
