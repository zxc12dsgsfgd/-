# 工作流规则设计（初版）

未实现或测试。规则使用固定枚举和结构化 JSON，由服务端校验，不执行用户代码。

## 规则结构示例
```json
{
  "name": "已读后添加标签",
  "enabled": true,
  "trigger": {"type": "paper_status_changed"},
  "filters": [{"field": "status", "op": "eq", "value": "read"}],
  "actions": [{"type": "add_tag", "tag_id": 1}]
}
```
触发类型：`paper_created`、`paper_status_changed`、`card_created`、`scheduled_check`。过滤字段和运算符按事件白名单校验；动作 `add_tag`、`set_paper_status`、`create_notification` 参数及所引用资源均须属于规则拥有者。模板包含待读超时、已读加标签、特定类型新卡片加标签；日期阈值为用户参数，限制正整数。

## 执行、去重和恢复
业务数据与事件同事务写入。后台进程扫描事件/到期任务并用原子更新申请租约；执行键对事件采用 `(workflow_id,event_id,entity_id)`，定时任务采用 `(workflow_id,本地日期,entity_id)`，并以非空规范键加唯一索引保障去重。规则条件、标签/状态/通知变更与成功执行记录置于同一数据库事务；失败回滚动作、另事务写脱敏失败记录。重试应重用执行键；失败状态可在租约过期后按策略重新申请，不能让唯一约束阻止恢复。最多 3 次自动尝试，指数退避，耗尽标失败并可供人工查看。

规则动作造成的状态变化产生后继事件，继承 chain_id 且深度加一；最多 5 层，超限记失败并终止链。事件重复、并发 worker、崩溃和重试需要针对真实 MySQL 集成测试，以上是设计目标。无规则动作调用外部 AI，因此数据库事务可覆盖这些动作；其他外部调用不保证恰好一次。

定时检查拟每分钟扫描到期项，每用户本地日期最多对同规则及对象执行一次；进程关闭时不运行，恢复后补扫当前日期，停机期间历史日期不逐日回补。待读超时按进入待读状态时间计算；如无该事件则以创建时间为起点。规则执行日志记录时间、对象、状态、失败代码及脱敏原因；可删除规则的历史记录保留方式在迁移时采用软删除或可空外键，详细实现需与日志保留一致。

## 2026-11-20 实现差异
目前只实现文献创建、状态变化、卡片创建触发，动作仅创建提醒。事件、成功运行及提醒与业务事务同步提交；失败回滚全部操作，没有独立失败记录、后台进程、定时扫描和重试。相同事件 ID 的重复顺序处理跳过，数据库唯一约束保护规则与事件组合；并发重复的恢复与事务行为尚未实测。因为没有触发其他业务变更的动作，目前不产生规则链。规则删除保留执行记录和提醒。

## 2026-11-20 动作和定时实现差异
独立 worker 每分钟扫描；超期依据文献创建时间，UTC 日期构造规则/文献稳定事件键，每日最多一次，重启后只检查当天。动作支持提醒、添加本人标签、更新文献状态；规则链超过 5 层回滚。同步事件失败回滚业务。扫描失败仅打印脱敏短消息并在下一轮重试，无持久失败原因、退避及单规则隔离；worker 持续运行、重启和并发尚未验证。与原设计的进入待读时间及用户时区口径不同。

## 2026-11-20 失败恢复实现
定时项失败在事务回滚后记录脱敏错误代码，按 60 秒起指数退避，上限 1 小时；每项独立处理，成功后标记恢复。仅当天扫描，跨日未恢复项不会自动回补；进程重启及多 worker 并发尚未实测。同步事件动作失败仍随业务事务回滚，无独立失败记录。

## 2026-11-20 跨日重试更新
仍启用且满足当前条件的规则/文献，优先重试最早未解决的失败；跨日成功时写入当日去重标记。重试使用当前规则配置。规则停用或删除、文献状态变化或不再满足条件时，失败不会自动解决；未记录的停机日不补跑。新数据库会话模拟跨日已验证，真实进程重启及多 worker 并发未验证。
