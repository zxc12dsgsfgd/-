# 数据库详细设计（初版）

状态：设计草案，未创建表或执行迁移。MySQL 使用 InnoDB、utf8mb4；版本和排序规则在环境验证后固定。所有时间为 UTC `DATETIME(6)`，API 返回带时区 ISO 8601。以下为计划，不保证已实现。

## 通用约定

主键 `id BIGINT UNSIGNED` 自增，外键类型一致；`owner_id` 指向 `users.id`，服务端查询及关联写入同时限制 owner。可变实体含 `created_at`、`updated_at`；非空除特别标注外均为必填。文本具体长度见下表，JSON 字段经 Pydantic 校验后写入，不执行代码。主键/FK 有索引；列表以 `(owner_id, created_at, id)` 等组合索引支撑稳定排序。数据库层约束不能替代跨用户授权。实际迁移应验证 MySQL 版本支持的约束行为。

## 删除与事务

删除文献需确认：删除文献笔记、文件记录和状态事件；卡片保留并将 paper_id 置空，同时保留来源摘录、页码及来源标题快照（卡片及版本均需保存该快照）。已有草稿来源和分享快照保留；分享不会随原文自动更新，可随时撤销。文件删除由清理任务在数据库提交后重试，严禁删除路径外文件。删除卡片时删除其版本、标签关系及卡片关系；既有草稿来源和分享快照保留。删除标签仅删除关联，不删除文献或卡片。删除前界面须说明。物理删除使历史周报对被删除文献/卡片的新增数可能变化；如果需要不可变历史统计需另行设计。

卡片更新与版本写入、文献状态与事件写入、规则副作用与执行记录应分别在同一事务。文件系统无法参与数据库事务：临时文件及清理任务、重启恢复须在实现时测试。备份应同时包含一致时间点的 MySQL 数据和文件目录；操作方案及恢复验证待部署阶段。
